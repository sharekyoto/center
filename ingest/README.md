# 取り込み — 六時間ごとの現像

`ingest/observe.mjs` が X・Threads・Instagram を巡回し、`data/` に書き出します。
盤（`grid-map.html` ／ `index.html`）は `CONFIG.INGEST.FEED` に `data/feed.json` を指すだけです。

```
observe.mjs            巡回の本体。cron で回す
contact.mjs            フィルム片（buildStrip）と一葉（buildLeaf）を焼く
board.mjs              座標の語彙。盤（template.html）と揃えること
x-auth.mjs             X への書き込み認証（OAuth 1.0a）
test-oauth.mjs         署名の自己検査。着手時に必ず一度走らせる
instagram-webhook.js   Cloudflare Workers に置く @メンションの受け口
```

> **API を叩く部分はまだ実機で動かしていません。**
> 画像の生成・座標の解釈・盤への反映は疑似データで一周確認済み。
> X / Threads / Instagram の仕様も料金も動くので、着手時に確認してください。

## 1. 何を拾うか

### 座標は要りません

**盤を開かないと座標が分からない、という状態では習慣は育ちません。**
だから座標を必須にしていません。覚えるのは `@alembicity` ひとつだけです。

| 投げたもの | どうなるか |
|---|---|
| `@alembicity` ＋ 写真 | **未定位の観測**。盤の「世界」タブに並び、誰かが座標を付けるのを待つ |
| `@alembicity #KYOTO_E6` ＋ 写真 | 坊（8×8 の 64 区画）に載る。**自分の一区画なら覚えられる** |
| `@alembicity #KYOTO_E6f3` ＋ 写真 | 町まで確定して載る |
| 未定位の投稿に `@alembicity #KYOTO_E6f3` で返信 | **定位**。位置が決まる。**撮った人でなくてよい** |
| 誰かの観測に `@alembicity` ＋ 言葉 で返信 | その写真への言葉。**座標は要りません** |

返信の相手は `referenced_tweets`（X）で辿るので、
**座標を書かなくても正しい写真に言葉が付きます。**
相手が分からないときだけ、座標／地点でいちばん新しい観測を選びます。

未定位の写真があるときは、束ね投稿の本文に
「位置の分からない写真が N 枚あります。心当たりがあれば、返信で座標を書いてください」を必ず添えます。
**これがいちばん摩擦の低い参加口で、しかも「この写真はどこか」という会話が勝手に生まれます。**

> **Threads と Instagram には返信の紐づけがまだありません。**
> X だけが `referenced_tweets` を返すためです。
> Threads / Instagram で言葉を足すときは、座標を書いてもらう必要があります。

### ハッシュタグでも @メンションでも拾います

どちらか一方ではありません。

```
X ／ Threads   #発酵都市観測 #KYOTO_E6f3
               @alembicity  #KYOTO_E6f3
Instagram      @alembicity #発酵都市観測 #KYOTO_E6f3   ← ＠が要る
```

**Instagram だけは @メンションが必須です。** ハッシュタグ検索が投稿者名を返さないので、
タグだけの投稿は全部 `0000` 号（名を残さなかった全員）に落ちます。
これは欠陥ではなく、**名乗るかどうかを投稿者の選択にしている**——という設計です。
盤の投稿口にも、その旨を書いて二つ並べてあります。

X の検索は `(#発酵都市観測 OR @alembicity) -is:retweet` の一本にまとめてあるので、
メンションを足しても読み取りの費用は増えません。
Threads は `q` を一つしか取らないので二回引きますが、Threads API は無料です。

### 盤の外（未踏の地）

```
#発酵都市観測 #N3499_E13574     北緯34.99 東経135.74
```

0.01度（緯度で約1.1km・経度で約0.9km）の升目。
**八つ溜まると、その升目の中心から標準寸法の盤が切り出されます**（`board.mjs / deriveBoard`）。

ただし **命名は運営** なので、生まれた盤に自動で名は付きません。
`data/boards-pending.json` に矩形だけが凍結され、
**名が付くまで、その盤の観測に座標は配られません。** 場所は、名より先に在ります。

運営がやること：`boards-pending.json` の一件に `"name":"NARA"` を書き足して
`boards.json` へ移す。次の現像から座標が配られます。

## 2. 三本の語る導線

「写真が先に来て、説明はあとから、別の人が付ける」を成立させている経路です。

1. **元の投稿に返信** — 写真と言葉が自然に結びつく。拡散はしない
2. **現像の投稿を引用して、座標かコマ番号（`02A`）を書く** — 拡散する
3. **一葉が出る** — 写真・座標・番号・言葉が1枚の画像になって出る。**語ることへの報酬がここ**

**3 が中心です。** 引用でも返信でもなく、言葉そのものが画像になって外へ出るので、
読んだ人は元の投稿を開かなくても、何を見てどう語られたかが分かります。

フィルム片にも一葉にも `@alembicity` を焼き込んであります。
**画像は引用されて独り歩きするので、画像自体が行き先を持っていないと、拡散が流入になりません。**

## 3. secrets

GitHub の **Settings → Secrets and variables → Actions** に入れます。

| 名前 | 何 | 要るか |
|---|---|---|
| `X_BEARER` | 検索（読み取り）用。app-only の bearer | **必須** |
| `X_API_KEY` | OAuth 1.0a ／ Consumer Key | **必須**（書き込み） |
| `X_API_SECRET` | OAuth 1.0a ／ Consumer Secret | **必須** |
| `X_ACCESS_TOKEN` | OAuth 1.0a ／ Access Token | **必須** |
| `X_ACCESS_SECRET` | OAuth 1.0a ／ Access Token Secret | **必須** |
| `X_USER_TOKEN` | OAuth 2.0 で試すとき用の代替 | 任意 |
| `THREADS_TOKEN` | Threads の長期トークン（60日ごとに更新） | 任意 |

**なぜ OAuth 1.0a なのか。** OAuth 2.0 のユーザートークンは約2時間で切れます。
cron で回す形では、切れるたびに refresh して secrets に書き戻す仕組みが要り、
「人的リソースが無いので自走させる」という前提と噛み合いません。
**OAuth 1.0a の access token には有効期限がないので、一度入れたら放っておけます。**

Variables（secrets ではなく **Variables**）に `DRY_RUN = 1` を入れると、
**投稿せずにログだけ出します。最初の1か月はこれで回してください。**

### 着手したら、まずこれ

```
node ingest/test-oauth.mjs
```

署名が1バイト狂うと X からは 401 が返るだけで理由が出ません。先に確かめてください。
（検証値は独立実装 `oauth-1.0a` と突き合わせて確定させたものです。
X の公式ドキュメントの署名例は、同じページのベース文字列と噛み合っていません）

## 4. 周期と費用

UTC の 21・3・9・15時 → **JST の 6時・12時・18時・24時。一日四回。**
UTC 9時（JST 18時）の回だけ、言葉が焼き込まれた一葉も出ます。

| 行為 | 回数／月 | 単価（推定） | 月 |
|---|---|---|---|
| 巡回（読み取り） | 120 | 約 $0.005 | $0.60 |
| 束ね投稿 | 120 | 約 $0.015 | $1.80 |
| 一葉 | 30 | 約 $0.015 | $0.45 |
| 初回返信 | 30人程度 | 約 $0.015 | $0.45 |
| | | **合計** | **約 $3.30**（¥600以内） |

**費用が人数で増えません。** 観測が10件でも1000件でも、現像ごとの投稿は1本です。
返信は初回の発番だけで、日次上限（既定20）を超えたら止まります。
番号の照会は盤の側が公開 JSON を引くので、API を一度も叩きません。

- **支出上限を必ず設定してください。** $20 も入れておけば暴走しても止まります
- **投稿に URL を入れない。** リンク入りは約 $0.20 で13倍、しかも伸びが落ちます
- 単価は公開レートカードが無く実測報告からの推定です。**最初の1か月は請求を毎週見てください**

四時間ごと（日6回）に戻すと月 $4.5 前後になり、¥600 を超えます。
削るなら巡回の回数です。**フィルム片と一葉は削らないでください**——
そこが「引用でバズる」経路の実体なので、削ると企画の中心が消えます。

## 5. 観測者番号

**番号は人ではなく、呼び名に与えられます。**

- SNS が違っても handle が同じなら同じ番号。名寄せはしません
- 名を変えれば別の観測者。別人が同じ名を使えば同じ観測者
- `#観測者0042` と書けば、現地カードの番号を名乗れます（先着一名）
- **名が取れなければ `0000` 号**。一人ではなく、名を残さなかった全員

## 6. 消え方

巡回のたびに画像 URL と permalink を叩きます。

| 状態 | 条件 |
|---|---|
| `faded` 褪色 | 画像が取れなくなった。言葉は残る |
| `lost` 欠落 | 投稿ごと消えた |

一時的な失敗では落としません。**運営が消すのではなく、放っておいたら褪せる**——
リンク切れがそのまま世界の物理法則になります。

## 7. 現像 ── フィルム片

その回に届いた観測を最大4つ、35mm フィルムの切れ端に焼いて **1枚**にします。

- 縦横がばらばらでも、同じ枠に流し込むので**投稿の見た目が毎回同じ**になります
- アップロードするメディアが **4件から1件**に
- 「写るんです」の色を**焼き込む**ので、X 上でも盤と同じ色になります
- 1コマは 460px。**原寸の転載ではなく観測票**になり、写り込んだ顔は判別できません
- 刻印はすべて英数字。日本語フォントの無い環境でも崩れません
- 切り抜きは**中央固定**。現像機は構図を選びません

焼いた分は `data/strips/` に残ります。`CFG.POST.strip` を `false` にすると文字だけになります。
`sharp` が要ります（`npm i sharp`）。ubuntu-latest でそのまま入ります。

### 二次現像 ── 一葉

- 出す時刻は `CFG.POST.leafHour`（UTC）。既定 **9 ＝ JST 18時**（いちばん読まれる回）
- 選ぶのは「言葉がいちばん多く付いた、まだ一葉にしていない観測」
- 焼いた分は `data/leaves/` に残り、同じ観測は二度出しません
- **和文を描くので日本語フォントが要ります。** workflow に `fonts-noto-cjk` を入れてあります

### 再掲の約束

- **「タグを付けた時点で観測票への再掲に同意」を、盤とプロフィールの両方に最初に書いてください。**
  後から取れません。**これが無いとフィルム片も一葉も出せません**
- `#再掲不可`（`#norelay`）を書いた投稿は、**盤には載りますが焼きません**（一葉からも外します）
- 「人が写っていない写真のみ」は**名誉規約で、機械には検査できません**。1コマ 460px が実質の緩和です

## 8. 引用リポスト

`CFG.POST.quoteOn` で条件を変えられます。既定は `['split','board']`。

- **受領は返信（静か）。引用リポストは事件のときだけ。**
  全観測を引用すると観測センターのタイムラインが自分の投稿で埋まり、一本あたりの重みが消えます
- 八つ目を落として**セルを割った人**を引用するのが、いちばん強い報酬になります
- **盤が生まれた**ときも出します。月に何度もない事件なので

## 9. 盤へつなぐ

`observe.mjs` は毎回 `data/feed.json` を書きます。

```js
// template.html の CONFIG
INGEST:{ FEED:'https://.../data/feed.json' }
```

**指した瞬間、DEMO データが消えて実データに切り替わります**（左上の「DEMO データ」も消えます）。
読めなければ警告をコンソールに出して、DEMO のまま静かに続けます。盤が白くなるほうが困るので。

```json
{ "at":"2026-08-23T18:00:00Z",
  "tally":  { "KYOTO/E6f3": 5 },
  "seeds":  { "N3465_E13519": 8 },
  "plates": { "KYOTO/E6": ["0007","0041"] },
  "boards": [ { "name":"NARA", "bounds":{} } ],
  "records":[ { "coord":"KYOTO/E6f3", "by":"0101", "kind":"photo", "state":"ok",
                "locatedBy":"0104",
                "img":"https://pbs.twimg.com/...", "permalink":"https://x.com/...",
                "tx":"...", "words":[{"by":"0103","state":"ok","tx":"..."}] } ],
  "drifting":[ { "id":"x:1001", "by":"0166", "img":"https://...", "permalink":"https://x.com/...",
                 "tx":"...", "words":[] } ] }
```

`drifting` が未定位の観測。盤の「世界」タブに「まだ位置の決まっていない観測」として並びます。
`locatedBy` は、その観測の位置を決めた人の番号（撮った人とは別のことがあります）。

`plates`（銘板）は書き出していますが、**盤側の表示はまだ未実装**です。

盤は `type="module"` で読み込まれ、格子を組む前に feed を待ちます。
**この順番を崩さないでください。** 先に格子を組むと、差し替えても座標が古いままになります。

## 10. Instagram

`instagram-webhook.js` を Cloudflare Workers に置き、Meta の webhook に登録します。
メンションが来ると GitHub の `repository_dispatch` を叩き、次の現像で取り込まれます。

| 環境変数 | 何 |
|---|---|
| `IG_VERIFY_TOKEN` | webhook 登録時に自分で決める文字列 |
| `IG_APP_SECRET` | Meta アプリのシークレット。**署名検証に必須** |
| `IG_TOKEN` | Graph API のトークン。本文・画像・投稿者名の取得用 |
| `GH_TOKEN` / `GH_REPO` | repository_dispatch 用 |

- `X-Hub-Signature-256` の検証を入れてあります。**これが無いと、URL を知った誰でも観測を捏造できます**
- webhook は `media_id` しか渡してこないので、Graph API で本文・画像・投稿者名を引いてから渡します。
  **`IG_TOKEN` が無いと username が取れず、その観測は 0000 号になります**
- `media_url` は署名付きで期限切れします。**permalink を必ず一緒に保存**しています

- **升目をまたいだ八つ**は、いまの実装では盤を生みません（同じ升目に八つ、で数えています）。

  タグは死にません。「この地点タグは KYOTO/E6f3 になった」という表が要ります
